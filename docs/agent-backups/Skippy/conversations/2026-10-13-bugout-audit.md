# Bug-Out audit (Skippy, 2026-10-13), read-only
Repo skiiwa67-collab/cellular-disaster-logistics @ one-to-many HEAD d744df7ba64005677a792c8e7e6994ab42c75223 (0.6.2). 0.6.1 = a1e7df7 (diff vs 09f9eed: Family.kt, MainActivity.kt, MapView.kt, DataTest.kt). Paths are relative to bug-out-toolset/; code lives in android/app/src/main/java/com/skiiwa/bugout/.

## HIGH
1. **The doc and code use different authority models.** The doc defines six tiers, A0 to A5 (PROGRAM-LOGIC.md "AUTHORITY SYSTEM"). The code's AuthorityTier has three: FEMA_IC, FIRE_EMS, CIVILIAN (Authority.kt:9-11). ATier A0-A5 is only a display badge string (Authority.kt:55-58) and drives no priority, so "highest authority present wins" isn't implemented. Fix: make one tier enum (A0-A5) the source of priority for Report, SyncDelta and Override.
2. **Nothing verifies authority claims.** The doc says A3+ needs an official-device code and fake claims get flagged ("Integrity" bullet; B4). The code has no code, signature or verification: a Report's tier is a free string (FeatureMenu.kt:10-13) and the app itself creates "A4" reports from user taps (MainActivity.kt:300). Any phone can claim A5. Fix: sign A3+ deltas with keys provisioned to official devices, show unverified claims as A0 plus a "claimed" flag, and add tests for spoofed claims.
3. **Overrides can strip hazards from routing.** The reunion check does flag hazards on the straight line (Family.kt:128), and the drawn line goes to a meet-point when one is blocked (MainActivity.kt:106). But the switch labelled "ignore my reports" drops ALL crowd-report hazards from routing, not just the user's own (MainActivity.kt:113, 199-201), and the doc lets a parent override FEMA/fire routing with no hazard-class limit (core principle "Family reunion priority"). Fix: an override may change the destination or priority but must never silently remove A3+/scenario hazards (fire, nuclear downwind) without a second confirm that names the hazard. Scope the switch to the user's own reports.
4. **Overrides never leave the phone, and the audit isn't trustworthy.** The doc says overrides sync over the mesh and up the chain (core principle; B1 step 8). AuditLog is in-memory only (Authority.kt:20-28). fromOverride exists (Authority.kt:50-51), but no code anywhere calls it (verified by grep). bandwidthShares is used only in a test. IDs are entries.size+1, which collide across devices, and nothing is hashed or signed. Fix: persist the log, put overrides on the sync queue, use UUID IDs plus a hash chain plus a device signature.
5. **Messages are deleted at handoff, so there is no delivery guarantee.** StoreForward.contact() clears the whole queue the moment any relay is touched (Family.kt:83-85). There are no retries and no per-message ack. A relay that dies mid-handoff loses the message, which breaks the doc's "delayed, never dropped" rule (core principle, line 30). Fix: keep each item until an end-to-end ack carrying its message ID arrives, and retry with backoff.
6. **The status shows "replied" when nobody replied.** Any incoming message flips ALL of my RELAYED messages to REPLIED (Family.kt:106-107), whatever it answers. "↩ sim reply" is the only source (MainActivity.kt:320). A parent may believe a child got a message they never received. Fix: use in-reply-to IDs and distinct states: queued, handed to relay, delivered (ack), read.

## MED
7. **The relay protocol is undefined.** There is no dedup, TTL/expiry, hop count, loop prevention or storage cap. SyncDelta has no TTL or hop fields (Authority.kt:31-34), and the queue is an unbounded MutableList (Family.kt:78). Fix: give each message a UUID plus a seen-set, a TTL and hop limit, a per-origin rate limit and a byte cap with an eviction policy (never evict SOS or kids' location).
8. **Some message IDs are unsafe and some ordering can starve traffic.** MainActivity sends with entityId = currentTimeMillis (MainActivity.kt:252), so two sends in the same millisecond, or from two phones, collide. FamilySync.order always puts Location first (Family.kt:72-73), so a flood of location deltas starves help requests. bandwidthShares has a floor (Authority.kt:40-46), but it isn't used by StoreForward. Fix: use UUIDs, and give SOS/Help top class, then coalesce location to the latest per person.
9. **Old authority orders never expire.** "Last authority, Nm ago" stays the main path indefinitely (PROGRAM-LOGIC "Last-known authority direction"), and a ground-confirmed GO has no expiry (OPEN QUESTIONS 1). Nothing implements either: unknown in code. Fix: add a TTL per scenario, a visual stale-decay warning after X min, and auto-downgrade to CAUTION.
10. **Starlink is only a demo button.** "Starlink" is a label on a demo relay button (MainActivity.kt:317) and an inventory item (Data.kt:44). There's no link detection, power budget, obstruction handling, cost model or fallback logic, though the doc's fallback ladder relies on it (B1 step 3), and the doc's "Starlink-equipped trucks get bandwidth priority" assumes truck availability. Direct-to-Cell capacity and availability: unknown. Fix: spec it as an opportunistic backhaul with a measured link state and a power/duty-rotation budget (B6 power grid), and never make it a single point.

## LOW–MED
11. **Hotspot filtering can hide nearby help.** Suggestions exclude schools and churches outright (Hotspots.kt:57), though these are often real shelters. The display only shows spots within 0.5 mi of a route (Hotspots.kt:63, 72-83), so an off-route shelter 0.6 mi away is hidden unless it has a staffed presence report. Presence reports are unauthenticated and the latest one wins (Hotspots.kt:87-91), so one false "staff 0" or "staff 5" can demote or promote a site. Fix: add a "show all nearby" toggle, a radius scaled to tier, multi-source plus tier-weighted presence, and an age limit on presence.
12. **Routes and reachability are straight lines.** Reachability, hazard crossing, reroutes and meet-points all use great-circle distance ×1.4 (Hotspots.kt:27-38; Family.kt:46-63, 124-131), so a route can cross a river with no bridge or go through a hazard between waypoints. Reroute checks are per hazard and only on the segment to home. Rogue Wi-Fi hotspots, privacy (two-way live location of kids to all members, Family.kt:69) and battery drain are not addressed in code: unknown. Fix: label everything "estimate" (partly done), add road-graph routing, minimize location precision/retention, and add an opt-in plus kid-safety review.
